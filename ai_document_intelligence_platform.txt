PROJECT OVERVIEW
----------------
Build a production-grade, fully hosted RAG (Retrieval-Augmented Generation) platform
where users can upload documents (PDFs), ask natural language questions, and receive
cited answers powered by an LLM. Everything runs on AWS with a clean Next.js frontend.

This is a personal portfolio project. Prioritize clean code, real deployment, and
production-grade architecture over speed. Take time to do it right.

TECH STACK
=============================================================

FRONTEND:
- Framework: Next.js 14 (App Router)
- Styling: Tailwind CSS
- Hosting: Vercel (free tier)
- Features: File upload UI, chat interface, citation display, auth pages

BACKEND:
- Framework: FastAPI (Python)
- Hosting: AWS EC2 t2.micro (free tier)
- Containerized with Docker
- Exposed via REST API

DATABASE:
- AWS RDS PostgreSQL (free tier) with pgvector extension
- Stores: document metadata, text chunks, vector embeddings, chat history

STORAGE:
- AWS S3 (free tier)
- Stores: raw uploaded PDF files

SERVERLESS:
- AWS Lambda (free tier)
- Triggered by S3 upload event
- Handles: PDF parsing, chunking, embedding, storing to pgvector

LLM:
- Groq API (free tier) — use llama3-70b-8192 or mixtral-8x7b model
- Used for: answer generation, query rewriting

EMBEDDINGS:
- HuggingFace sentence-transformers (free, runs locally in Lambda)
- Model: all-MiniLM-L6-v2 (lightweight, fits Lambda memory)

CI/CD:
- GitHub Actions
- On push to main: build Docker image → push to AWS ECR → deploy to EC2

INFRASTRUCTURE AS CODE:
- Terraform
- Provisions: EC2, RDS, S3, Lambda, ECR, IAM roles, security groups

AUTH:
- NextAuth.js (Next.js side)
- JWT tokens passed to FastAPI for protected routes

SYSTEM ARCHITECTURE — END TO END FLOW
=============================================================

DOCUMENT UPLOAD FLOW:
1. User logs in via Next.js frontend (NextAuth)
2. User uploads a PDF via the UI
3. Next.js sends PDF directly to FastAPI backend
4. FastAPI uploads raw PDF to S3 bucket
5. S3 upload triggers AWS Lambda function automatically
6. Lambda:
   a. Downloads PDF from S3
   b. Extracts text using PyMuPDF (fitz)
   c. Chunks text into ~500 token segments with 50 token overlap
   d. Generates embeddings using sentence-transformers (all-MiniLM-L6-v2)
   e. Stores chunks + embeddings into RDS pgvector table
   f. Updates document metadata table (status: processed)
7. Frontend polls FastAPI for document status and shows "Ready" when done

QUERY / CHAT FLOW:
1. User types a question in the chat UI
2. Next.js sends question + document_id to FastAPI
3. FastAPI:
   a. Generates embedding for the question
   b. Runs pgvector similarity search to find top 5 most relevant chunks
   c. Builds prompt: [system prompt] + [retrieved chunks with source labels] + [user question]
   d. Calls Groq API with the prompt
   e. Returns answer + source chunk references
4. Frontend displays answer with clickable citations showing source text

DATABASE SCHEMA
=============================================================

-- Enable pgvector
CREATE EXTENSION IF NOT EXISTS vector;

-- Users table
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(255),
    created_at TIMESTAMP DEFAULT NOW()
);

-- Documents table
CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id),
    filename VARCHAR(255) NOT NULL,
    s3_key VARCHAR(500) NOT NULL,
    status VARCHAR(50) DEFAULT 'processing', -- processing | ready | failed
    page_count INTEGER,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Chunks table with vector embeddings
CREATE TABLE chunks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index INTEGER NOT NULL,
    content TEXT NOT NULL,
    embedding vector(384),            -- all-MiniLM-L6-v2 outputs 384 dims
    page_number INTEGER,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Create vector similarity search index
CREATE INDEX ON chunks USING ivfflat (embedding vector_cosine_ops);

-- Chat history table
CREATE TABLE chat_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID REFERENCES documents(id),
    user_id UUID REFERENCES users(id),
    role VARCHAR(20) NOT NULL,        -- user | assistant
    content TEXT NOT NULL,
    cited_chunk_ids UUID[],           -- array of chunk ids cited
    created_at TIMESTAMP DEFAULT NOW()
);

=============================================================
LAMBDA FUNCTION LOGIC (handler.py)
=============================================================

Trigger: S3 PutObject event

Steps:
1. Parse S3 event to get bucket + key
2. Download PDF from S3 to /tmp/
3. Extract text per page using PyMuPDF (fitz)
4. Chunk text:
   - Target chunk size: 500 tokens
   - Overlap: 50 tokens
   - Preserve page number metadata per chunk
5. Generate embeddings:
   - Load all-MiniLM-L6-v2 from HuggingFace
   - Batch embed all chunks
6. Connect to RDS via psycopg2
7. Insert all chunks + embeddings into chunks table
8. Update document status to 'ready'
9. Handle errors: update status to 'failed', log to CloudWatch

Lambda config:
- Memory: 1024 MB (needed for sentence-transformers)
- Timeout: 5 minutes
- Runtime: Python 3.11
- Layer or container image for dependencies

TERRAFORM RESOURCES TO PROVISION
=============================================================

1. S3 Bucket
   - Enable versioning
   - Block all public access
   - Add S3 event notification → Lambda trigger on PutObject

2. RDS PostgreSQL
   - Instance: db.t3.micro (free tier)
   - Engine: postgres 15
   - Enable pgvector extension on first run
   - Private subnet, only accessible from EC2 security group

3. EC2
   - Instance: t2.micro (free tier)
   - AMI: Ubuntu 22.04
   - Security group: allow port 80, 443, 22
   - Attach IAM role with S3 + ECR read permissions

4. Lambda
   - Runtime: Python 3.11
   - Memory: 1024 MB
   - Timeout: 300 seconds
   - IAM role: S3 read + RDS access + CloudWatch logs
   - Environment variables: DATABASE_URL, S3_BUCKET

5. ECR Repository
   - Store Docker images for FastAPI backend

6. IAM Roles
   - Lambda execution role
   - EC2 instance role (ECR pull + S3 access)
